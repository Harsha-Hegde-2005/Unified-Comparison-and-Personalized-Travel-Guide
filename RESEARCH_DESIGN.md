# Phase 4: Formal Research Design & Experimental Protocol

## Executive Summary
This document establishes the formal research questions, hypotheses, baseline models, evaluation metrics, test scenarios, and ablation protocols for the empirical evaluation of the proposed **Coordinated Multi-Agent Journey Recommendation Framework**.

---

## 1. Formal Research Questions & Hypotheses

### Research Question 1 ($RQ_1$)
> *How can an asynchronous multi-agent coordination architecture integrate heterogeneous public transit feeds (BMTC GTFS, Namma Metro), private ride-hailing APIs (cabs, auto-rickshaws), personal vehicle fuel models, and dynamic environmental context (weather forecast, traffic congestion) to generate personalized multimodal journey recommendations?*

- **Hypothesis $H_1$**: Asynchronous parallel candidate generation across specialized mobility agents will reduce total end-to-end recommendation latency by at least **35% to 50%** compared to sequential monolithic execution, particularly for complex multimodal routes requiring multi-graph traversal.

### Research Question 2 ($RQ_2$)
> *What is the impact of dynamic environmental signals (rain forecast, outdoor exposure, road traffic congestion) on recommendation scoring stability and transport mode selection?*

- **Hypothesis $H_2$**: Contextual weather exposure scoring will dynamically shift top-ranked recommendations from high-exposure modes (walking, ordinary buses) to weather-sheltered modes (Namma Metro) during rainfall events, increasing average weather suitability scores by $\ge 30\%$ without exceeding reasonable user cost thresholds.

### Research Question 3 ($RQ_3$)
> *How effectively does the multi-criteria utility normalization and Explainable AI (XAI) agent articulate quantitative trade-offs between competing journey metrics (time, cost, emissions, comfort)?*

- **Hypothesis $H_3$**: The XAI agent will accurately identify the dominant decision drivers (e.g., time saved per rupee spent, rain avoidance) and achieve 100% factor-attribution consistency across diverse user preference weight profiles (`cost`, `time`, `convenience`, `eco`).

## 2. Defensible Baselines ($B_1$ – $B_5$)

To evaluate the proposed framework rigorously, we define 5 progressive baseline models:

| Baseline ID | Name | Description | Routing Logic | Context & Preference Support |
| :--- | :--- | :--- | :--- | :--- |
| **$B_1$** | **Shortest-Time-Only** | Minimizes total travel duration strictly ($T_{\text{travel}}$). | Single-objective shortest path. | No cost weight, no weather, no traffic. |
| **$B_2$** | **Lowest-Cost-Only** | Minimizes monetary fare strictly ($C_{\text{fare}}$). | Single-objective minimum fare lookup. | Ignores travel duration & weather. |
| **$B_3$** | **Static Weighted Monolithic** | Evaluates fixed weighted sum of cost, time, and comfort. | Sequential mode calls, static scoring. | Fixed weights ($0.50$ cost, $0.50$ time), no weather/traffic. |
| **$B_4$** | **Monolithic Context-Aware** | Existing repository implementation (`backend/recommender.py`). | Sequential pipeline execution with weather/traffic factors. | Dynamic weather & traffic penalties, single-threaded execution. |
| **$B_5$ (Proposed)** | **Coordinated MAS Framework** | Novel multi-agent architecture (`research/mas/`). | Parallel multi-agent candidate generation & contract-net negotiation. | Fully personalized, dynamic weather exposure, live traffic delays, XAI attribution. |

## 3. Evaluation Metrics

1. **Recommendation Latency ($L$, ms)**:
   - Total end-to-end execution time from query arrival to final ranked response. Measured via high-resolution timers (`time.perf_counter()`).
   - Metrics reported: Mean, Median, Standard Deviation ($\sigma$), and 95th Percentile ($P_{95}$).
2. **Candidate Generation Latency ($L_{\text{agent}}$, ms)**:
   - Individual computation time for each mode agent ($A_{\text{bmtc}}, A_{\text{metro}}, A_{\text{cab}}, A_{\text{veh}}$).
3. **RAM Memory Consumption ($M$, MB)**:
   - Peak RSS memory footprint measured using `psutil`.
4. **Pareto Utility Score ($S_{\text{utility}}$, $0-100$)**:
   - Composite weighted utility score generated by multi-objective normalization.
5. **Weather Exposure Index ($E_{\text{weather}}$, $0.0-1.0$)**:
   - Quantification of outdoor rain exposure risk for recommended routes.
6. **XAI Explanation Attribution Accuracy ($A_{\text{xai}}$, %)**:
   - Percentage of test cases where the generated XAI text correctly reflects the mathematical metric differentials ($\Delta \text{Cost}, \Delta \text{Time}, \Delta \text{Weather}$).

## 5. Formal Ablation Protocol

To isolate the scientific contribution of individual system components, we perform 4 ablation experiments:

1. **Ablation 1 ($Abl_{\text{no-weather}}$)**: Removes the Context Agent's weather module ($A_{\text{ctx, weather}}$), setting weather suitability to 1.0.
2. **Ablation 2 ($Abl_{\text{no-traffic}}$)**: Removes the Context Agent's traffic congestion module ($A_{\text{ctx, traffic}}$), setting free-flow speed across all road legs.
3. **Ablation 3 ($Abl_{\text{no-user}}$)**: Replaces personalized user preference weights with a fixed uniform weighting vector ($w_k = 1/6$).
4. **Ablation 4 ($Abl_{\text{no-mas}}$)**: Replaces asynchronous multi-agent coordination with synchronous sequential execution (equivalent to $B_4$).
