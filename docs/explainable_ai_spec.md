# Explainable AI (XAI) Specification

This document details the engineering specifications for the Explainable AI (XAI) engine within UTRS. The engine is responsible for generating human-readable explanations that justify the system's route recommendations based on cost, time, convenience, and external factors like weather and traffic.

---

## 1. Concept & Rationale
When recommending a multi-modal route in Bengaluru, a single option is rarely "best" in every metric. For example:
* **Metro** is fast and immune to traffic, but may require walking transfers.
* **Cabs** are direct and convenient, but expensive and vulnerable to traffic jams.
* **BMTC ordinary buses** are very cheap, but slow.

Explainable AI (XAI) solves the "black-box" recommendation problem by clarifying the mathematical trade-offs to the commuter in simple English, allowing them to make informed decisions.

---

## 2. Multi-Criteria Trade-Off Evaluation

The XAI engine evaluates alternative journeys ($J_i$) generated by the routing engines using a scoring matrix.

### Scoring Variables
* $C_i$: Total monetary cost (₹)
* $T_i$: Total travel time (minutes)
* $W_i$: Walking distance (km)
* $X_i$: Number of transfers/interchanges

### Trade-Off Ratios
The engine calculates relative differentials between the top 3 options:
$$\Delta \text{Time} = T_j - T_i$$
$$\Delta \text{Cost} = C_i - C_j$$

If Option A is faster but more expensive than Option B, the system calculates the **value of time saved** to justify the recommendation:
$$\text{Cost-per-hour saved} = \frac{\Delta \text{Cost}}{\Delta \text{Time}} \times 60$$

* If the cost-per-hour is $< \text{₹}100$, the system explains: *"Option A is highly recommended because it saves you 30 minutes of travel time for only ₹15 more."*
* If the cost-per-hour is $> \text{₹}400$, the system explains: *"Option B is recommended as the value-choice; Option A is 10 minutes faster but costs ₹150 more."*

---

## 3. Explanation Generation Pipeline

The backend component `features/explainable_ai.py` acts as a template-based and heuristic post-processor for the `/api/compare` endpoint:

```
[Journey Options list] 
      │
      ▼
[Heuristic Evaluation] ──► Compare relative differentials (Cost, Time, Transfers)
      │
      ▼
[Context Checks]       ──► Query weather status, operational delay warnings
      │
      ▼
[Explanation Parser]   ──► Select appropriate template and fill variables
      │
      ▼
[Enriched CompareResponse] (includes explanation string per option)
```

### Explanation Templates

| Case | Heuristic Rule | Generated Explanation Text |
| :--- | :--- | :--- |
| **Cheapest Public** | Lowest fare, moderate time | *"Best budget option. Save up to ₹[X] compared to cabs by taking the direct BMTC ordinary bus."* |
| **Metro Superior** | Speed-up > 20m, costs < ₹50 more | *"Highly recommended: Metro bypasses significant road traffic on [RoadName], saving you [Y] minutes for an extra ₹[Z]."* |
| **High Convenience** | Transfers = 0 | *"Recommended for convenience: A direct door-to-door ride avoids [N] transfers and walking legs, though it costs more."* |
| **Weather Alert** | Heavy Rain active | *"Weather Recommendation: Metro is chosen over bus routes to avoid waterlogging delays around [Station/Stop]."* |

---

## 4. UI Design & Layout

In the React UI:
* **Recommendation Tag**: Placed as a badge at the top of the option card (e.g., `CHEAPEST`, `FASTEST`, `RECOMMENDED BY AI`).
* **AI Summary Block**: A micro-section inside the card styled with a soft background containing the explanation text.
* **Comparison Matrix**: Under the "Compare" tab, differences are highlighted visually (e.g., green text indicating time saved or cost reduced).
